# Траты — учёт личных расходов студента

Веб-приложение, в котором студент фиксирует траты и сразу видит, сколько ушло за месяц и на какие категории. Расчёт выполняется только по данным, которые ввёл пользователь: заранее подготовленных итогов в проекте нет.

## Какую проблему решает

Повседневные расходы трудно оценить по заметкам в телефоне: нет общего итога и не видно структуры трат. Приложение даёт три вещи, которых не хватает при ручном подсчёте — список всех расходов за месяц, автоматический итог и разбивку по категориям с долями.

Основной пользователь — студент, который вносит траты вручную в одной валюте (тенге, ₸).

## Что реализовано

Обязательный сценарий кейса:

- **Форма ввода** — сумма, категория, дата; описание необязательно. Некорректные данные отклоняются с понятным сообщением рядом с полем (пустая сумма, ноль и отрицательные значения, текст вместо числа, больше двух знаков после запятой, неизвестная категория, неверная дата).
- **Список расходов** за выбранный месяц, сгруппированный по дням с подытогом за день. Любую запись можно удалить; после удаления 6 секунд доступна кнопка «Вернуть».
- **Итоги** — общая сумма за месяц и суммы по категориям. Пересчитываются при добавлении, удалении и смене месяца.
- **Совпадение сумм** — сумма по категориям всегда равна общему итогу; остаток округления передаётся крупнейшей категории. Под таблицей категорий выводится результат самопроверки.
- **Сохранение данных** — записи хранятся в `localStorage` и остаются после обновления страницы и перезапуска браузера.
- **Единая валюта** — конвертации нет, все суммы в ₸.

Дополнительно (сверх обязательного сценария):

- месячный бюджет с прогресс-баром и предупреждением о превышении;
- аналитика месяца: средний и медианный расход, средние траты в день, число дней с тратами, самый крупный расход, прогноз итога на конец месяца;
- сравнение с предыдущим месяцем в процентах;
- график трат по дням месяца и цветная полоса структуры расходов;
- фильтр списка по категории;
- экспорт месяца в CSV;
- REST API на FastAPI + SQLite и кнопка «Отправить в базу» для переноса записей из браузера в базу;
- тёмная тема, адаптивная вёрстка, работа с клавиатуры.

## Как работает решение

1. Пользователь открывает страницу — приложение подставляет текущую дату и последний месяц с записями.
2. Вводит сумму, выбирает категорию и дату, при желании добавляет описание, нажимает «Добавить расход».
3. Данные проходят валидацию. При ошибке поле подсвечивается и под ним появляется текст с причиной, запись не сохраняется.
4. Корректная запись попадает в `localStorage`, список и все итоги перерисовываются.
5. В шапке экрана видна общая сумма за месяц, под ней — полоса со структурой по категориям; в правой колонке таблица «По категориям» и блок аналитики.
6. Кнопка «×» удаляет запись, итоги пересчитываются немедленно.
7. Переключение месяца в шапке меняет список и все расчёты.
8. После обновления страницы (F5) данные остаются на месте.

## Технологии

| Слой | Используется |
|---|---|
| Frontend | HTML, CSS, JavaScript (ES5-совместимый, без фреймворков и сборщика) |
| Хранение на клиенте | `localStorage` |
| Backend | Python 3.10+, FastAPI, Uvicorn, Pydantic v2 |
| База данных | SQLite (модуль `sqlite3` из стандартной библиотеки, без ORM) |
| Шрифт | Onest (Google Fonts) |

Внешние API, платные сервисы и AI-модели в работе приложения не используются. Код разрабатывался с помощью AI-агента, но на runtime это не влияет.

## Архитектура проекта

```
expense-tracker/
├── frontend/
│   ├── index.html            разметка интерфейса
│   ├── css/styles.css        стили, токены цвета, тёмная тема
│   └── js/
│       ├── analytics.js      расчёты: итог, категории, дни, динамика
│       ├── storage.js        localStorage, валидация, клиент API
│       └── app.js            отрисовка и обработка действий пользователя
├── backend/
│   ├── app/
│   │   ├── main.py           FastAPI: маршруты, обработка ошибок, отдача фронтенда
│   │   ├── analytics.py      те же расчёты на сервере
│   │   ├── database.py       SQLite: схема и запросы
│   │   ├── schemas.py        валидация входных данных (Pydantic)
│   │   └── categories.py     справочник категорий и валюта
│   ├── test_scenario.py      автопроверка сценария из раздела 7 ТЗ
│   └── requirements.txt
├── build_demo.py             сборка фронтенда в один HTML-файл
└── README.md
```

Как взаимодействуют компоненты:

- **Фронтенд самодостаточен.** Источник правды — `localStorage`; `analytics.js` считает все итоги в браузере. Приложение полностью выполняет требования кейса без запущенного сервера.
- **Бэкенд опционален.** При старте фронтенд проверяет `/api/health`. Если сервер доступен, кнопка «Отправить в базу» копирует записи в SQLite через `POST /api/expenses/bulk`; если недоступен — кнопка отключается и работа продолжается на локальных данных.
- **Расчёты продублированы** в `frontend/js/analytics.js` и `backend/app/analytics.py` с одинаковой логикой, поэтому итоги совпадают на клиенте и на сервере.
- FastAPI дополнительно раздаёт статику фронтенда, так что весь проект поднимается одной командой.

### Эндпоинты API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/health` | проверка доступности сервера |
| GET | `/api/meta` | категории, валюта, список месяцев с данными |
| GET | `/api/expenses?month=ГГГГ-ММ` | список расходов (месяц необязателен) |
| POST | `/api/expenses` | добавить расход |
| DELETE | `/api/expenses/{id}` | удалить расход |
| POST | `/api/expenses/bulk` | загрузить записи из браузера в базу |
| GET | `/api/analytics/summary?month=ГГГГ-ММ&budget=` | итог, категории, динамика, прогноз |
| GET | `/api/analytics/categories?month=ГГГГ-ММ` | итог и суммы по категориям |

Интерактивная документация после запуска: `http://localhost:8000/docs`.

## Установка и запуск

### Вариант 1. Только фронтенд (достаточно для проверки кейса)

**macOS / Linux:**

```bash
git clone <ссылка-на-репозиторий>
cd expense-tracker/frontend
python3 -m http.server 5500
```

**Windows (PowerShell):**

```powershell
git clone <ссылка-на-репозиторий>
cd expense-tracker\frontend
python -m http.server 5500
```

Открыть `http://localhost:5500`. Файл `frontend/index.html` также можно просто открыть двойным кликом — приложение работает и без сервера.

### Вариант 2. Фронтенд + backend + база данных

**macOS / Linux:**

```bash
cd expense-tracker/backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

**Windows (PowerShell):**

```powershell
cd expense-tracker\backend
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python -m uvicorn app.main:app --reload --port 8000
```

Если `Activate.ps1` не запускается с ошибкой про выполнение скриптов, один раз разрешить это для текущего пользователя:

```powershell
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
```

Если после установки команда `uvicorn` не находится, использовать `python -m uvicorn ...` — так модуль запускается напрямую, без зависимости от PATH.

Открыть `http://localhost:8000` — фронтенд и API работают на одном порту. Файл базы `backend/expenses.db` создаётся автоматически при первом запуске.

### Сборка одного HTML-файла для деплоя

**macOS / Linux:**

```bash
cd expense-tracker
python3 build_demo.py     # результат: dist/index.html
```

**Windows (PowerShell):**

```powershell
cd expense-tracker
python build_demo.py      # результат: dist\index.html
```

## Как проверить решение

### Сценарий из раздела 7 ТЗ, вручную

1. Открыть приложение, выбрать текущий месяц.
2. Добавить три расхода (дату можно оставить сегодняшней):
   - `1500`, категория **Еда**
   - `600`, категория **Транспорт**
   - `900`, категория **Еда**
3. Ожидаемый результат: общий итог **3 000 ₸**, Еда — **2 400 ₸**, Транспорт — **600 ₸**.
4. Удалить расход на `900` кнопкой «×».
5. Ожидаемый результат: общий итог **2 100 ₸**, Еда — **1 500 ₸**, Транспорт — **600 ₸**.
6. Нажать F5. Все записи и итоги сохраняются.

### Проверка валидации

Отправить форму с суммой `0`, `-100`, `abc` или с пустой датой — запись не создаётся, под полем появляется сообщение об ошибке.

### Автоматическая проверка

```bash
cd backend
python3 test_scenario.py     # Windows: python test_scenario.py
```

Скрипт прогоняет тот же сценарий (включая пустой список и совпадение суммы категорий с итогом) и печатает статус каждой проверки. Запускается без сервера и без установки зависимостей.

### Частые проблемы при запуске (Windows)

- **`python3` не найден** — в Windows команда называется `python`, не `python3`.
- **`uvicorn` не распознан как команда** — виртуальное окружение не активировано или `uvicorn` не установился. Проверить активацию (в начале строки должно быть `(.venv)`), затем `pip install -r requirements.txt`. Запускать сервер можно и в обход PATH: `python -m uvicorn app.main:app --reload --port 8000`.
- **Ошибка про политику выполнения скриптов при активации** — один раз выполнить `Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned`, затем повторить активацию.
- **`cd` не находит папку** — команды в этом README рассчитаны на запуск из корня репозитория; если вы уже внутри `backend`, не добавляйте `backend` к пути повторно.

## Данные и интеграции

Расходы вводятся пользователем вручную. Внешние наборы данных, банковские интеграции, платежи, регистрация и синхронизация между устройствами не используются. Обращений к сторонним API нет; единственный внешний ресурс — шрифт Onest с Google Fonts, при отсутствии интернета подставляется системный шрифт.

## Ограничения

- Нет аккаунтов и синхронизации между устройствами: данные привязаны к конкретному браузеру. Очистка данных сайта удалит записи.
- Одна валюта (₸), конвертации нет.
- Backend хранит данные в SQLite без авторизации — режим прототипа, не для публичного развёртывания.
- Синхронизация односторонняя: браузер → база, с полной заменой содержимого таблицы.
- Категории заданы списком, добавлять свои через интерфейс нельзя.
- Редактирование существующей записи не реализовано — запись нужно удалить и добавить заново.
- Нет повторяющихся расходов, вложений и чеков.
- Прогноз итога на месяц — линейная оценка по среднедневным тратам, без учёта сезонности.
